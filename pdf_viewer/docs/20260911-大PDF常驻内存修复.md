# 大 PDF 常驻内存修复

## 已确认问题

Edge 崩溃转储确认 `main.11fe8ea7.js` 所在 Renderer 发生 OOM。上一版协作式渲染降低了单次卡顿，但程序仍可能长期同时持有 PDF.js 文件数据、React 状态中的完整 `ArrayBuffer`，以及矢量切页使用的整份 pdf-lib 解析文档。

## 本次处理

- 网页端超过 64MB 的 PDF 不再把完整 `ArrayBuffer`永久保存在 React 状态；查看仍由原 File 与 PDF.js 完成，导出时从 File 按需读取。
- 草稿文件指纹只读取文件首尾各 64KB，不再为了指纹读取整份 PDF。
- 多页矢量提取完成后释放整份 pdf-lib 解析文档，只保留已经提取出的矢量结果；单页使用后的解析文档最长空闲两分钟也会释放。
- Renderer 诊断增加常驻 PDF 字节数、pdf-lib 文档数量及矢量缓存页数。

标注、草稿、OCR/MinerU、矢量结果、页面磁盘缓存及导出质量均不改变。大文件的首次导出需要重新从 File 读取一次源PDF，可能比过去增加一次文件读取耗时，但导出峰值内存反而更低。
