# 标识偏移修复说明

## 原因及源码修复

后台预取将服务端按像素上限缩小的页面图片固定记录为 UI scale=0.625，
但当前页直接加载使用实际 renderScale / 2。这使两条显示路径的底图比例不同。
本次 A1 页实际 renderScale 约为 1.22234623，正确 UI scale 约为 0.611173115。
错误缓存显示的底图缩小约 2.2%，在其上画出的标识坐标也随之缩小；
导出或重开使用正常底图时，标识表现为向左上偏移。

已统一两条预取路径与直接加载的比例计算，并将截图缓存升级为 snapshot:v4。
这些代码错误在仓库最早提交 9048c80 中也存在。源码修改尚未部署。

最先修复的异步截图问题作为独立风险保留：旧代码在 Canvas.toBlob 回调中读取当时的
UI 缩放，可能把旧尺寸与新缩放组合；文档切换后的迟到回调也缺少代际校验。
现在同步捕获渲染比例/尺寸，并丢弃过期文档回调。回归测试覆盖两种时序，
没有把它当成本次文件的根因。

## 已生成的文件

针对本次问题样例，已生成独立的可编辑版、标注版及 JSON 修复报告。
输出名分别在输入文件名末尾增加“坐标修复”和“修复报告”，不覆盖原文件。

共有 5,192 个标识，分布在 258 页。两份输出均为 283 页，几何与原文件逐页一致。
可编辑版只修改标识的 startX/startY/endX/endY，保留 ID、文本、字号、框配置及原始保存时间。
标注版按相同比例调整已有图片标识层，因此其中的文字和边框也随图片层放大约 2.26%。
这是保持现有图片外观的修复方式；可编辑版再次由应用导出时仍按原有字号/框配置绘制。

修复前后已校验原输入文件 SHA-256 未变；可编辑版所有页面内容流未变，
标注版仅 258 页最后的标识图片内容流改变。可编辑附件已重新读取验证。
另放大检查第 3、19 页并查看第 101 页，确认原先左上偏移的引导线回到管线附近。
该修复针对确定的整体比例错误，保留手工标注本身的位置误差，不是重新识别焊点。

## 使用修复脚本

依赖项目已有的 PyMuPDF，已在本机 1.28.0 验证。使用同目录的
render_pdf_page_cache.py 计算逐页实际栅格比例，不依赖 OpenCV 或 NumPy。
在仓库根目录执行：

```powershell
python pdf_viewer/scripts/repair_annotation_cache_scale.py "问题文件-可编辑版.pdf" --annotated "问题文件-标注版.pdf"
```

脚本默认按已确认的 1.25 栅格比例、600 万像素上限恢复。若其他部署使用不同配置，
通过 --preferred-scale、--pixel-cap 指定；--factor 可显式覆盖恢复比例。
不要对没有此缺陷的 PDF 批量执行。

输出写到输入文件所在目录，也可用 --output-dir 指向一个已存在目录。
原文件不覆盖；同名输出存在时拒绝写入；已修复文件带有修复标记，再次修复会拒绝。
脚本先写临时 PDF、重新打开验证，再生成最终文件名，并记录原文件哈希与逐页比例。
此脚本支持本案这种旋转为 0、MediaBox/CropBox 一致的页面。
