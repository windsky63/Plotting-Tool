# PDF 文档按需加载与内存释放

## 修改前备份

`runtime/document-memory-20261014/source-before-20261014-082840.zip`

本轮在 20261013-02 的基础上修改。已有页面图片缓存、700ms 回退、草稿保存及恢复继续沿用。

## 原因与修改

页面只显示当前页，并不意味着 PDF 文档只读取当前页。此前查看器始终挂载 React-PDF Document；其 File 加载路径读取整份 ArrayBuffer，缓存源数据，并复制缓冲交给 PDF.js Worker。图片已经可以显示时，这条路径仍然运行。

浏览器的服务器图片模式现在使用独立的按需文档管理器：

- 已有服务器缓存时，从现有 status 接口取得总页数，图片和标注可以直接显示，不启动 PDF.js 文档解析。
- 缓存查询未在 700ms 内提供页数时启动本地 PDF 回退。已有页面的图片失败或超时仍通过原 700ms 回退机制触发本地渲染。
- 文字、矢量、批量处理按原 getPage 接口请求页面时，才读取源文件。并发请求共用一次读取与一个 PDF.js 文档，缓冲直接传给 PDF.js，避免 React-PDF Document 源缓存中的额外完整副本。
- 完整解析仍是整份文件解析，并未增加服务器单页 PDF 接口。
- 页面句柄只长期保存轻量几何信息。文档空闲 60 秒后销毁 PDF.js 任务及 Worker，清空页面原始对象；仍存在的句柄后续调用文字、矢量或渲染方法时可自动重载。
- 文件读取、页面读取、文字/矢量操作及画布渲染期间有活动计数，空闲销毁等待这些操作结束。切换文件时销毁旧会话，旧读取结果不能启动新解析或更新新文件。
- 连续浏览和打印按需启用渲染；非浏览器图片模式继续使用原 Document。密码 PDF 保留输入密码流程。
- 图片模式的页面尺寸沿用现有图片缩放换算，并同步给工具栏及 OCR 尺寸状态。

实现位置：`src/utils/onDemandPdfDocument.js`、`src/components/pdf/OnDemandPdfDocument.js`、`src/components/PDFViewer.js`。

## 内存指标的含义

第 60 页编辑后，CDP 主页面 backingStorageSize 采样约 7 MB；上一轮同一 PDF 的对应指标约 374.3 MB。这是主执行上下文缓冲区指标，不是浏览器总进程内存、全部 Worker 内存或 GPU 内存，也不是全过程峰值。两次测试缓存准备条件不同，不应把这组数值宣传为浏览器总内存下降比例。打开文件的元数据读取完成时，仍观察到约 374 MB 的临时缓冲区，后续采样才回落到约 7 MB。

打开文件读取标注元数据、缓存未命中、识别和导出仍可能临时读取完整 PDF。此修改消除了普通缓存图片浏览对完整 PDF 常驻解析的依赖，不能保证任意大小文件和设备均不会 OOM。

## 草稿链路与部署

本机仍使用 IndexedDB；云端仍使用 `/api/annotation-drafts/save`、`/api/annotation-drafts/latest`，沿现有 Node 代理转发。服务器代理、OCR 服务及接口均未修改。

部署只需更新本次构建的前端静态资源，保留服务器 app-config.json、草稿和页面缓存。旧 20261013-02 部署包不包含本轮文档按需加载修改。
