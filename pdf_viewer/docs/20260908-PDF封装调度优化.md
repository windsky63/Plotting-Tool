# PDF 封装调度优化

## 改动范围

- `src/utils/pdfSerialization.js`：沿用 pdf-lib 1.17.1 的 PDFWriter；每个实例按约 12ms 工作时间片让出主线程，替换固定每 50 个对象的等待频率。不修改全局定时器或第三方依赖。
- `src/App.js`：封装调用接入新调度；记录 `[PDF封装耗时]`，最近一次数据也可通过 `window.__lastPdfSerializationTiming` 查看。
- `src/utils/pdfExportProgress.js`：封装阶段展示计算结构、写入数据的实际遍历进度。

保持 `useObjectStreams: false`、`updateFieldAppearances: false`，不改标注 Canvas 绘制、PNG 编码、分辨率、字体、圈、引线、页面旋转和输出格式。不会增加一个完整 PDF 的 Worker 副本，不并发生成两份大文件。遇到写入错误直接上报，不自动再分配大缓冲重试；库接口不兼容时保留原保存方法。

## 验证和限制

此前启动的测试在处理停止请求时已结束：9 项检查通过，涵盖字节一致、旋转/裁剪/附件、延迟后恢复工作时间片、失败不重试、进度变化。桌面 625 页文件的独立封装基准也已结束：原调度 14,191ms，新调度 1,025ms，输出长度和 SHA-256 一致。这是 Node 环境的封装对比，不是用户电脑上整个标注版导出耗时的保证。

用户随后要求不再进行大文件测试，已遵从；日常回归样本改为 12 页，实际大文件表现交由用户测试。构建后仅部署本次修改，不额外调整拖动、加点或 OCR。
