落图工具服务器更新包：20261014-04 PDF 无损优化与标注附件替换

新增功能
- Web 导出可编辑版、标注版及快捷保存时调用服务端无损优化；不降低图片分辨率或质量。
- 合并重复对象及完全重复的数据流，清理无引用对象，进行无损压缩。
- 逐页进行有界预览渲染、文字、尺寸、旋转检查，并校验附件内容、书签和元数据。保留草稿身份尾标。
- 所有标注数据统一写入一个当前 annotations.json 附件；保留其他附件、命名目标和书签，清除旧 Keywords 标注载荷。
- 优化成功时，旧的不可达 JSON 对象由服务端垃圾回收清理。失败回退文件仍可能保留不可达旧对象，但当前附件入口唯一。
- 优化服务不存在、忙碌、超时、校验失败或体积没有减小时，使用完整的未优化导出文件；失败有提示。
- 浏览器导出采用 Blob 分块封装，避免为了优化上传再拼成整份连续字节数组。

资源边界
- 每个 Node 进程最多接收一个优化任务（含上传及下载阶段），忙碌时回退普通导出。
- 单文件最大 512 MiB；任务总时限 120 秒，前端 125 秒超时。临时文件在任务结束时删除。
- 这是导出后的优化，需要额外上传与等待，不能消除之前 PDF 解析的内存峰值；不承诺避免所有 OOM。
- 签名或加密文件不进入本轮优化。只保证经验证的无损对象去重，不按图片外观相似度强行合并。

部署（本次包含后端更新，不能只覆盖前端）
1. 备份服务器现有静态目录和 scripts 目录，保留 app-config.json、草稿、缓存和运行数据。
2. 将 server_update/scripts 下的三个文件复制到服务器 pdf_viewer/scripts。
3. 在服务器执行 python scripts/install_pdf_export_optimizer.py。脚本只插入两个接入点，备份原服务器文件；不会替换服务器特有配置。如找不到接入点将退出且不修改。
4. 确认服务器使用的 Python 安装了 PyMuPDF（import fitz）。可用 PDF_OPTIMIZE_PYTHON 指定解释器绝对路径，也兼容 PDF_PAGE_CACHE_PYTHON。未设置时 Windows 使用 python，Linux 使用 python3。
5. 按原管理方式重启现有 Node 服务，沿用当前端口和所有草稿/OCR配置。
6. 将 build_prod 内容复制到实际 STATIC_ROOT，保留原 app-config.json；Ctrl+F5 刷新，不清除浏览器网站数据。
7. GET /api/pdf-export/optimize/status 应返回 available:true。导出一份可编辑 PDF 后重新打开核对标注。
