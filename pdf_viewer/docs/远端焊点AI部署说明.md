# 远端焊点 AI 部署说明

## 目标与边界

本说明用于把焊点 AI 的**训练和推理**部署在一台具备 NVIDIA GPU 的内网电脑上。落图小程序本机只负责：

- 渲染焊点区域图片并提交给远端；
- 将 AI 结果与现有矢量规则识别合并；
- 把 AI 单独识别出的焊点交给人工确认。

AI 是辅助能力，不能替代现有规则：规则已识别的焊点不会被 AI 删除；AI 单独发现的焊点默认不直接写入标注，必须在多页处理的候选列表中人工采纳。远端模型未就绪、服务不可达或推理失败时，小程序自动继续使用原有规则识别。

## 远端实施范围

以下能力都应在远端 GPU 电脑上实现和运行。本机落图工具不训练模型、不保存模型权重、不进行整图深度推理，只负责提交请求、显示候选和人工确认。

1. **图纸规范化**：将客户端提交的焊点区域图片统一为固定方向、分辨率、线宽和切片规格；识别图纸模板或项目类型，记录缩放比例和区域坐标。不同项目不能直接混用版式特征。
2. **AI 焊点候选模型**：从图像中输出焊点中心、置信度、类别和模型版本；采用重叠切片、跨切片去重和困难负样本过滤。模型不直接生成焊口编号、寸径、接头形式或最终标注。
3. **矢量与拓扑验证**：远端接收或按需补充页面矢量信息后，建立“管线—管件—焊点”局部拓扑；用靠近、贴合、在线上、连接端点、同一管线等逻辑验证 AI 候选，过滤文字、尺寸线和孤立噪声。
4. **材料表与 OCR 约束**：利用材料表中的 PIPE、FITTINGS、QTY、SIZE 和描述信息，为候选结果补充或校验管径、接头形式、管件数量和项目规则；材料表只提供约束，不替代焊点位置判断。
5. **人工确认和数据闭环**：保存 AI 候选、规则结果、人工采纳/拒绝结果、最终标注及原因；将人工确认后的样本按 PDF/项目版本幂等更新，训练完成后记录数据集版本、模型版本、阈值和验证指标。
6. **服务化与任务管理**：推理、训练、样本处理和评估使用独立队列；在线推理优先，训练不得占满显存或阻塞识别。服务不可用时必须明确返回失败状态，客户端自动退回规则识别。

远端目标是形成“**AI 候选 → 拓扑/材料约束校验 → 人工确认 → 样本回流 → 重新训练与灰度验证**”的闭环，而不是用纯图像模型直接替换现有落图规则。

## 现有客户端已具备的能力

- 默认远端地址：`http://192.168.32.61:8767`。
- 可通过生产目录中的 `app-config.json` 配置 `weld_ai_server_url` 覆盖默认地址。
- 多页处理中有“远端 AI 焊点辅助”开关，当前默认关闭。
- 工具栏可“确认焊点训练样本”上传人工确认的数据；也可“导出训练包”得到 ZIP。
- 训练包包含 `images/page_XXXX.png`、对应 `labels/page_XXXX.json` 和 `manifest.json`；标签是完整 PDF 页面的归一化焊点中心坐标 `xNorm/yNorm`。

## 推荐实施顺序

### 1. 准备远端设备

建议使用 NVIDIA GPU，显存 12 GB 或以上更合适；8 GB 也可先进行小规模推理和训练验证。系统可以是 Windows + WSL2 或 Ubuntu。远端电脑需能从落图电脑访问，且仅在内网开放 TCP `8767`。

先确认以下项目：

```bash
nvidia-smi
python --version
```

安装与显卡 CUDA 驱动匹配的 PyTorch、Python 3.10/3.11、FastAPI、Uvicorn、Pillow、NumPy、OpenCV 和训练框架。不要在落图电脑安装训练环境或加载模型。

### 2. 收集训练数据

训练数据必须来自人工核对后的落图结果，不直接把规则自动识别结果当作真值。

建议先收集不同项目、不同清晰度、不同管径和不同标注密度的图纸，至少覆盖：普通直管、弯头、三通、支管台、阀门附近、密集焊点和无焊点区域。第一版建议准备至少数百页、数千个已确认焊点；数据越多越稳定。

在落图工具中完成核对后，点击“导出训练包”。每个 ZIP 应保留原始文件名、日期和项目来源；人工后续再次修正同一页时，以最新版本覆盖旧样本，避免同页存在互相矛盾的标签。

### 3. 选择模型和训练格式

当前训练数据只保存焊点**中心点**，因此推荐使用单类别中心点检测模型：

- 首选：热力图/关键点检测模型。输入为图纸切片，输出焊点中心热力图，再经局部峰值和非极大值抑制得到坐标。
- 可选：将中心点扩展为固定大小的方框后，训练 YOLO 单类别目标检测模型。该方案实施快，但固定框对不同 PDF 比例的适应性略弱。

无论选择哪一种，服务最终均只需输出中心坐标和置信度。训练与验证必须按“项目或 PDF 文件”划分训练集、验证集，不能把同一 PDF 的相邻页同时分进训练集和验证集。

推理建议采用 `1024–1280 px` 切片、约 `20%` 重叠、跨切片去重；这与客户端接口约定一致。模型输出需要做置信度阈值过滤和距离去重，并记录模型版本。

### 4. 实现远端服务

远端服务建议用 FastAPI 实现，监听 `0.0.0.0:8767`。必须实现以下接口：

#### 健康检查

`GET /api/weld-ai/health`

模型可用时返回：

```json
{
  "status": "ready",
  "available": true,
  "modelLoaded": true,
  "modelVersion": "weld-center-v1"
}
```

若服务已启动但尚未加载模型，必须返回 `modelLoaded: false`；不得伪造空成功结果。

#### 提交推理任务

`POST /api/weld-ai/jobs`

客户端请求会包含项目、PDF 身份、页码、页面尺寸、焊点区域和 PNG Data URL。服务可直接返回完成结果，也可返回异步任务：

```json
{ "jobId": "job-1", "status": "queued" }
```

异步任务由：

`GET /api/weld-ai/jobs/{jobId}`

查询。完成结果格式如下：

```json
{
  "status": "done",
  "modelVersion": "weld-center-v1",
  "detections": [
    {
      "id": "det-1",
      "xNorm": 0.4521,
      "yNorm": 0.3187,
      "confidence": 0.97,
      "class": "weld"
    }
  ]
}
```

`xNorm/yNorm` 必须相对于**完整 PDF 页面**归一化，不能相对于切片或焊点区域。服务也可以返回区域图像像素坐标 `x/y`，客户端会换算，但完整页面归一化坐标更可靠。

#### 接收人工确认样本

`POST /api/weld-ai/training-samples/confirm`

每次提交一页的原始页面 PNG 与已确认标签。使用 `sampleId` 幂等覆盖：同一页重新确认后更新旧样本，而不是新增重复样本。

服务需允许来自落图站点的 `GET`、`POST`、`OPTIONS` 跨域请求；推理队列与训练任务队列必须分开，训练不能阻塞在线识别。

详细字段约定可同时参照仓库中的 [weld-ai-remote-api.md](weld-ai-remote-api.md)。

### 5. 启动与网络配置

服务启动示例：

```bash
uvicorn app:app --host 0.0.0.0 --port 8767
```

在远端电脑放行内网防火墙端口 8767；不要直接暴露到公网。若远端 IP 不是 `192.168.32.61`，在落图工具生产目录的 `app-config.json` 增加：

```json
{
  "weld_ai_server_url": "http://远端电脑内网IP:8767"
}
```

修改后刷新落图小程序即可读取新地址。建议把服务配置为开机自启，并将模型权重、样本库、任务日志和服务代码放在独立目录，定期备份。

### 6. 上线验收

1. 从落图电脑访问 `GET /api/weld-ai/health`，确认 `available` 与 `modelLoaded` 均为 `true`。
2. 选取未参加训练的实际 PDF，先不开启 AI 跑一次规则识别并保存结果。
3. 再开启“远端 AI 焊点辅助”，对比规则一致数、AI 单独候选数、漏点数和误点数。
4. 只人工采纳正确的 AI 单独候选；错误候选保留为模型改进样本，不直接进入最终标注。
5. 达到稳定准确率后再扩大使用范围。AI 开关应保持默认关闭，按项目或图纸类型逐步启用。

## 交给远端电脑 Codex 的实施任务

### 已提供的远端服务源码

仓库中的 `remote_weld_ai/` 已包含首版可运行服务：

- `app.py`：8767 推理、健康检查、异步候选任务和人工确认样本接收；
- `model.py`：单类别焊点中心热力图网络；
- `train.py`：按 PDF 分组拆分训练/验证/测试集的远端训练脚本；
- `requirements.txt` 与 `README.md`：远端独立环境安装和启动方式。

该服务在没有模型权重时必须维持 `modelLoaded: false`，客户端会回退到规则识别。远端首次运行只需完成环境安装、样本接收与健康检查；达到人工确认样本数量后才运行 `train.py`，训练完成重启 8767 服务加载权重。

请先让 Codex 完成以下检查，再开始写服务或训练：

1. 检查 GPU 型号、显存、驱动、CUDA 与可用磁盘空间；
2. 读取本说明及 `docs/weld-ai-remote-api.md`，确认接口字段不改动；
3. 建立远端项目目录，分开保存服务代码、模型权重、训练集、人工确认样本、任务日志和评估结果；
4. 检查已有训练 ZIP 的数量、标签数量和项目分布，并按 PDF/项目划分训练、验证和独立测试集；
5. 先实现健康检查和返回固定测试结果的端到端服务，再接入真实模型；
6. 实现统一切片、去重、模型候选输出和候选日志；
7. 实现矢量拓扑、OCR/材料表约束的校验模块，输出每个候选被保留、降级或拒绝的原因；
8. 使用独立测试 PDF 验证坐标能准确回到原 PDF 页面，并统计召回率、误检率、人工采纳率和单页耗时；
9. 最后才训练、加载真实权重，并记录模型版本、训练数据版本、阈值和验证指标，先以小范围灰度方式开启。

不要在模型尚未验证时把 `modelLoaded` 设为 `true`，也不要让 AI 自动覆盖规则焊点或自动生成最终标注。
